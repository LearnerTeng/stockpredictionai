# 四条可选择的新闻模拟线

新闻页新增独立多选：DeepSeek、Ultra、实验特征策略、当前持仓基准。勾选决定运行哪些回放及显示哪些曲线；
在“后台新闻分析”中单独勾选并保存需要运行的模型。回放选择不会改变后台设置。
取消所有模型后保存可停止新任务入队；已入队任务仍会处理。

## 启动

```powershell
python -m pip install -r backend/requirements.txt
python -m alembic upgrade head
python backend/app.py
# 另一个终端，专门处理新闻实验，不要求配置 embedding key
python backend/scripts/research_worker.py --news-only --interval 60 --batch-size 10
# 前端终端
npm run dev
```

在忽略的 `backend/.env` 设置 `NVIDIA_API_KEY`，不要提交密钥。
`LLM_DEEPSEEK_MODEL` / `LLM_ULTRA_MODEL` 独立指定实际端点模型 ID，默认分别为
`deepseek-ai/deepseek-v4.1-flash`、`nvidia/nemotron-3-ultra-550b-a55b`。
端点可用性、JSON Schema 支持和账户配额必须用实际账户验证；不支持的响应会失败并重试，不会解析成中性分数。
旧文本任务 `LLM_RESEARCH_*`、`LLM_EXPLANATION_*`、`LLM_SENTIMENT_*` 也可以独立切换供应商和模型；
未配置时保留现有 OpenAI 路径。embedding 继续独立配置。

## 数据和四条线

供应商原始分数仍在原有新闻关联表中。每个模型任务额外冻结当时读到的原始分数，保存文档版本、模型、供应商、
配方版本和完成时间。两个模型只读取相同新闻与股票信息，不读取供应商分数或对方输出。
有供应商分数也会执行独立模型任务，不受原有分类器的供应商快捷路径影响。

- DeepSeek / Ultra 分开保存事件、未经校准的情绪分数、股票、引文、日期、金额、币种、期间、比较口径与未知因素。
- 实验特征线 v1 为 `0.4 × DeepSeek + 0.4 × Ultra + 0.2 × 供应商分数`。
  同一新闻版本的三项都齐全才计算，缺少任一项就不生成这篇新闻的组合特征。
- 股票级信号为最近 7 个自然日已完成新闻的分数均值。使用原有正分排名、容量限制和次日成交引擎。
  整个信号日没有证据时保持现有持仓，不把缺失视作清仓信号；有证据时负分可退出。
- 持仓基准固定起始份额、不调仓，仍处理数据集明确给出的分红、拆股等事件。

组合权重是待验证实验规则，并未训练或证明有盈利能力。量化收益预测和现有交易账户的评分/成交逻辑不受影响。

v3 要求每只股票有独立的分数与引文。每次回放默认固定为当时配置的供应商、模型 ID 和 v3 提示词。
如需重放旧版本，可在数据集的 `model_pins` 中为 deepseek 或 ultra 指定完整的 `provider/model/version`。
v2 的文章级分数仅用于单股票文档；多股票旧稿没有可区分的逐股票信号。结果报告记录实际选用的版本。

## 回放与持仓快照

新闻页可以选择账户并捕获当前持仓快照。导入同一个 PIT JSON 行情数据集后多选四条线运行。
回放沿用 `examples/portfolio-replay.json` 数据格式；每个 asset 还需 `symbol`，并增加：

```json
{
  "holding_snapshot": {
    "as_of": "2026-08-31T12:00:00Z",
    "cash": 90000,
    "quantities": {"demo-a": 10, "demo-b": 20}
  }
}
```

该片段是格式示例，不能用来证明过去真实持仓。真实历史快照必须来自当时保存的账户记录。
使用页面捕获的当前快照时会替换文件中的起始份额、现金和时间，只能用于此后交易日的前向比较。
如需历史回放，不捕获当前快照，直接导入含真实历史快照的文件。
没有 `cash` 时沿用配置的 initial_cash 作为总资本；有 cash 时以现金加首日开盘持仓估值确定总资本。

四条线使用同一初始现金、份额、行情、调仓参数和成本假设；缺失行情/股票映射会拒绝运行。
当前引擎仅支持 USD 美股，不能将日股或多币种持仓直接混入比较。
新闻可用时间、分析完成时间、修订版本都按当日截点过滤；更正稿已知后，不再用旧稿分析填补缺失。
没有可用模型证据的线显示 insufficient-evidence，不伪造净值曲线。

结果以内容哈希记录输入、配方及所选线，分别保留各线成交、现金、持仓、净值和引用任务 ID。
保存在 app_settings 的独立 `news-comparison:` 命名空间，不修改现有账户。
页面显示最近一次结果；同一结果重复运行不会重复保存。

## 运行限制及下一步

后台任务按文档、模型、输入配方缓存，行锁领取；调用超时 45 秒，失败指数退避，最多 5 次，重启后事务回滚恢复。
缺少密钥的任务保持 pending，五分钟后再检查，不记录为中性新闻。
当前为单 worker 顺序调用；多进程会通过 PG 锁分配任务，但没有全局账户配额控制，免费端点建议只运行一个 worker。
单次入队处理最近 100 个文档；目前没有自动拉取整套 PIT 行情或每日自动运行四线回放，需手动导入数据并运行。
长文输出截断、JSON 不合法或引文不匹配均拒绝。逐字引文校验仍不等于语义正确，真实中英日标注集与人工复核仍必需。
模型调用目前只在后台新闻任务中持久记录耗时/token；交互式解释及问答保留原有记录方式。

本轮没有提供真实端点的收益或质量结论；需配置账户后做接口验收，再逐日积累前向比较。
参考：[NVIDIA Chat Completions](https://docs.api.nvidia.com/nim/reference/llm-apis)、
[OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。
